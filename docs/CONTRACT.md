# Desktop contract

Renderer: React/TypeScript. Backend: Electron main ES modules (no direct Node access in renderer). Main exposes `window.desktop.invoke(method, args?) => Promise<any>` and `window.desktop.onEvent(callback) => unsubscribe`. Mutations return the result described below; a `state` event triggers a state refresh. Public state masks provider and bridge secrets; `settings.gatewayToken` remains available for local client setup. Browser connector tokens and pairing nonces are never included in public state. The browser preview displays the interface only; operations require desktop IPC.

State returned by `state:get`: `{projects,conversations,providers,settings,gateway,bridge,bridgeProfiles,bridges,browserConnector}`. Project `{id,name,path,createdAt}`. Conversation `{id,title,projectId,providerId,model,mode:'plan'|'build',messages:[],status:'idle'|'running'|'error',createdAt,updatedAt,archived?:boolean}`. Message `{id,role:'user'|'assistant'|'tool',content,createdAt,toolName?,approval?:{id,type:'write'|'command',path?,content?,original?,command?,status:'pending'|'approved'|'rejected'},artifact?:{name,content}}`. Provider `{id,name,type:'openai'|'anthropic'|'gemini',baseUrl,models:string[],defaultModel,hasApiKey,headers?:Record<string,string>,managedBy?:'browser-connector'}`. Settings `{theme:'light'|'dark',systemPrompt,maxSteps,gatewayPort,gatewayToken,gatewayAutoStart,bridgeExecutable,bridgeConfig,bridgePort}`. gateway `{running,port,url,error?}` bridge `{running,port,error?,logs:string[]}`.

IPC methods and args:
- `state:get`, `project:add` `{path?}` (native directory dialog when absent), `project:remove` `{id}` (remove reference only)
- `conversation:create` `{projectId?,providerId?,model?,mode?,title?}` => Conversation; `conversation:update` `{id,title?,archived?,providerId?,model?,mode?}`; `conversation:send` `{id,content}` => immediate acknowledgement, runner background; `conversation:stop` `{id}`; `approval:resolve` `{id,approved:boolean}`
- `provider:save` `{id?,name,type,baseUrl,apiKey?:string,models:string[],defaultModel,headers?}` (omitted key preserves key; empty string removes), `provider:remove` `{id}`, `provider:models` `{id}` => string[] (network discovery); `provider:test` `{id,model?}` => `{ok,message,providerId,providerName,model,endpoint}` (a fixed short generation request, defaulting to the saved default model; no discovery request, conversation history, project data, or tools)
- `settings:save` partial settings; `gateway:start`, `gateway:stop`, `bridge:start`, `bridge:stop`, `bridge:choose` `{kind:'executable'|'config'}` => chosen path
- `workspace:list` `{projectId,path?:string}` => `{name,path,type:'file'|'directory'}[]` (path relative root); `workspace:read` `{projectId,path}` => `{path,content}`; `workspace:write` `{projectId,path,content,original?:string}` => `{path,content}`; `workspace:search` `{projectId,query}` => `{path,line,text}[]`; `workspace:git` `{projectId}` => `{branch,status,diff}`
- `terminal:run` `{projectId,command,id?}` => `{id}`; `terminal:stop` `{id}`; output event `{type:'terminal',id,text,done?,exitCode?}`. Bounded non-interactive shell command runner, not a PTY.
- `shell:openExternal` `{url}`; `shell:reveal` `{path}`; `window:action` `{action:'minimize'|'maximize'|'close'}`.

Events via onEvent: `{type:'state'}` after changes; `{type:'delta',conversationId,messageId,text,content}` during model streaming (content is cumulative); `{type:'terminal',...}`. Agent sends tools using read_file/list_files/search_files/propose_file/run_command/create_artifact. Reads are scoped to the selected project. Plan mode forbids mutations and commands. Multiple conversations can run concurrently.

Conversation `permissionMode` is `ask` (default), `auto-edits`, or `full`. `conversation:create` and `conversation:update` accept this field. Transitions into `full` must include `confirmFullAccess: true`; invalid modes/confirmation types reject. Permissions cannot change while the conversation is running. Existing invalid/missing persisted values become `ask`. The runner snapshots permissions per run. `ask` requests human approval for every file write and command; `auto-edits` automatically approves file writes only; `full` automatically approves writes and commands. Automatic actions have a persisted approval card with `status:'approved'`, `autoApproved:true`, and `permissionMode`. Plan mode, cancellation, scoped file access, read-before-write, backups, and stale-content checks remain enforced in every mode. Model tool arguments cannot change the policy.

Provider module exports `discoverModels(provider,{signal?}={}) => Promise<string[]>`, `complete(provider,body,{signal,onDelta?}={}) => Promise<OpenAIChatCompletion>`, `streamCompletion(provider,body,{signal?}={}) => AsyncGenerator<OpenAIChatChunk>`. Provider internally includes `apiKey` in main only. Completion body standard OpenAI with messages/tools/model/stream/temperature etc. Native Anthropic and Gemini adapters translate; gateway normalizes all.

Version 1.2.0 adds `bridgeProfiles` and `bridges` arrays to `state:get`, while retaining the legacy `bridge` object and Gemini settings. Profile `{id,name,providerId,launchMode:'external'|'managed',executable,args:string[],cwd,env:Record<string,string>,healthUrl,startupTimeoutMs}` uses masked environment values in public state. Runtime `{id,running,starting,state:'stopped'|'starting'|'ready'|'error',logs:string[],error?}` is not persisted. Readiness reports a connection check, not successful inference.

Bridge IPC: `bridges:save` accepts profile fields and returns the public profile; `bridges:remove` `{id}`; `bridges:start`, `bridges:stop`, `bridges:check` `{id}` return runtime status; `bridges:choose` `{kind:'executable'|'directory'}` returns a selected absolute path. Save does not launch a process. Start/check may remain pending until ready, failed, or cancelled; Stop can be invoked concurrently. External Stop disconnects without killing a process. Managed Stop terminates the owned foreground process tree. A linked provider cannot be removed. Profile and provider connection edits are locked while running/connected/starting, but model lists/defaults/names can be saved. Unknown legacy bridge profile arrays fail closed instead of overwriting state.

Environment values are encrypted in desktop storage. Omitted `env` preserves it; `{}` clears it; `********` retains an existing value for that key. Managed provider URLs must be loopback. A custom health URL must share the linked provider origin, uses provider authentication, and does not follow redirects. Missing health URL checks the model-list endpoint. The desktop forwards args exactly without a shell and never downloads, installs, or logs into a website adapter on Save/Start.

Version 1.3.0 adds `browserConnector` runtime state: `{running:boolean,url:string,paired:boolean,pendingPairings:{id,extensionId,createdAt}[],sites:{id,connected:boolean,busy:boolean,error?:string}[],error?:string}`. Site IDs are `claude`, `chatgpt`, `deepseek`, `qwen`, `zai`, and `gemini`. `url` is the local model API base, normally `http://127.0.0.1:4319/v1`. `paired` means an extension token has been approved; it does not prove the extension is online. A missed heartbeat clears site readiness and fails pending requests. `connected` reflects a detected supported composer, not successful authentication or generation. `busy` includes queued and active requests. Pairing, readiness, jobs, and errors are runtime data; state-change events refresh the renderer.

Browser IPC:

| Method | Arguments | Result and behavior |
| --- | --- | --- |
| `browser:start` | None | Returns connector state. Starts the loopback listener and creates or updates the generated OpenAI-compatible **Connected Chrome** provider, its encrypted API key, and all six website aliases. Concurrent starts share one operation. |
| `browser:stop` | None | Returns connector state. Stops the listener, cancels pending requests, and clears pairing. Desktop conversations using this provider must be stopped first. |
| `browser:approve` | `{id}` | Approves an unexpired pending pairing and returns connector state. Only one extension can be paired; revoke it before approving a replacement. |
| `browser:revoke` | None | Cancels pending requests and clears pairing while keeping the listener running; returns connector state. |
| `browser:openSetup` | None | Copies the bundled extension into the versioned user-data folder, copies its path to the clipboard, reveals `manifest.json`, opens Chrome's extensions page, and returns `{path}`. Chrome still requires the user to select **Load unpacked**. |
| `browser:openSite` | `{siteId}` | Opens the allowlisted service URL in Chrome and returns `{opened:siteId}`. It does not log in or select a model. |

The generated provider is identified internally by `managedBy:'browser-connector'`. Its connection and removal are locked while the connector runs; names and model-list edits remain allowed. Starting the connector restores its six supported aliases: `claude-web`, `chatgpt-web`, `deepseek-web`, `qwen-web`, `zai-web`, and `gemini-web`. These choose websites; model selection and account entitlements remain on each website. Arbitrary custom model IDs are supported through ordinary configured API providers, not through this connector's fixed website aliases.

The browser service has two separate HTTP interfaces on the same loopback listener. `GET /v1/models` and `POST /v1/chat/completions` require the generated provider bearer token and reject browser origins, extension-ID headers, and cookies. The desktop uses this provider through the existing agent/provider stack; local clients can use the separate gateway and its token to reach namespaced browser models. Model listing is static and proves no account access. Completions accept text messages and function definitions within a combined 100,000-character limit, with one pending request per website and a 180-second request timeout. `stream:true` returns one buffered SSE completion followed by `[DONE]` after the website response completes; it is not live token streaming. There is no usage/token-count claim.

Extension transport routes are `POST /connector/pair` `{extensionId,nonce}`, `POST /connector/pair/status` `{id,nonce}`, `POST /connector/heartbeat` `{sites}`, `GET /connector/jobs`, and `POST /connector/results` `{id,siteId,result}` or `{id,siteId,error}`. Pairing requires desktop approval and a matching random nonce; pending requests expire after five minutes. The approved extension uses a separate bearer token and its matching extension origin or `X-Connector-Extension-ID` header. Website origins and cookies are rejected. Jobs are delivered once; result IDs, site IDs, allowed tool names, tool choice, and JSON arguments are validated. Cancellation IDs are returned during polling/heartbeats. Stopping, revoking, timing out, losing the client, or losing the heartbeat fails the request; stale results are rejected. Desktop pairing is not persisted, so restart requires pairing again.

The extension uses visible DOM controls in fresh task tabs. Existing conversations, drafts, password inputs, and verification pages are not submitted. Only a new assistant response with an observed completion signal is returned; output is buffered, and unsupported layouts fail. Tool envelopes are parsed from the whole response and still pass through the existing desktop permission policy. The extension never executes project tools itself. Synthetic DOM and transport tests do not establish live compatibility with the current websites or a user's account. See [browser setup and limitations](BROWSER-CONNECTOR.md).

Workspace module exports class `WorkspaceService` methods `list(root,relative='')`, `read(root,relative) => {path,content}`, `write(root,relative,content,original?)`, `search(root,query)`, `git(root) => {branch,status,diff}`, `run(root,command,{id,onData,onDone,signal}={}) => {id,stop,done:Promise<{exitCode,output}>}`. WorkspaceService methods async except run. Agent creates artifact messages without disk writing.

Version 1.4.1 separates model discovery from generation validation. `provider:test` requires nonempty assistant text and includes the tested provider/model/endpoint in its result. Browser provider tests first inspect the matching in-process connector state for startup, pairing, website presence, and availability. The renderer opens Settings on the current conversation provider and applies a different saved provider/model only on explicit selection; testing and saving do not change conversation routing.
